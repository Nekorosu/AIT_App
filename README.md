# AIT_App — электронный журнал

Учебное desktop-приложение электронного журнала на **Avalonia UI / .NET 9 / MySQL**.

Проект начинался как перенос WPF/MSSQL-приложения на кроссплатформенный стек и затем был расширен: добавлены журнал оценок, отчётность, планирование сессий, управление учебными данными, роли пользователей, BCrypt-аутентификация, аудит действий и экспорт в Excel.

## Возможности

- авторизация пользователей с хранением паролей в виде BCrypt-хешей;
- разделение интерфейса преподавателя и администратора;
- журнал оценок по группам и дисциплинам;
- добавление, изменение и удаление оценок;
- планирование экзаменационных сессий;
- отчёт по сессии и показателям успеваемости;
- работа со студентами и преподавателями;
- экспорт таблиц в `.xlsx` через ClosedXML;
- настройка подключения к MySQL из приложения;
- аудит значимых действий пользователей.

## Технологии

- .NET 9
- Avalonia UI 11
- MySQL / MariaDB
- MySqlConnector
- ClosedXML
- BCrypt.Net-Next

## Запуск

### Требования

Для разработки необходимы .NET 9 SDK, MySQL 8+ (или совместимая MariaDB) и исходная схема базы `electronic_journal`.

> Важно: текущий `migrations.sql` не является полной схемой БД. Он содержит изменения для уже существующей базы. Полный bootstrap-скрипт исходной схемы пока не хранится в репозитории.

### 1. Подготовка базы данных

Создайте/восстановите исходную базу `electronic_journal`, после чего примените миграции:

```bash
mysql -u USER -p electronic_journal < migrations.sql
```

Для локальной демонстрации можно затем загрузить тестовые данные:

```bash
mysql -u USER -p electronic_journal < mysql_seed_data.sql
```

**Внимание:** `mysql_seed_data.sql` предназначен для тестовой базы и очищает существующие учебные данные перед заполнением.

### 2. Настройка подключения

Скопируйте `config.example.json` в `config.json` и укажите свои реквизиты:

```json
{
  "ConnectionString": "Server=127.0.0.1;Port=3306;Database=electronic_journal;User=root;Password=;"
}
```

`config.json` находится в `.gitignore`, поэтому локальные реквизиты подключения не попадают в Git. Если файла нет, приложение использует локальную строку подключения по умолчанию; её можно изменить через окно настроек.

### 3. Сборка и запуск

```bash
dotnet restore
dotnet build
dotnet run
```

## Демо-учётные записи

После применения `mysql_seed_data.sql` доступны:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Преподаватель | `teacher` | `2222` |
| Администратор | `admin` | `admin` |

Эти данные предназначены только для локальной демонстрационной базы.

## Безопасность и конфигурация

Пароли пользователей хранятся в БД как BCrypt-хеши. SQL-запросы с пользовательскими значениями должны выполняться через параметры. Локальный `config.json` исключён из Git, чтобы не публиковать пароль к БД.

Проект является учебным desktop-приложением. Текущая модель ролей в первую очередь управляет доступностью функций интерфейса и не должна рассматриваться как полноценная security boundary для недоверенной среды.

Версия проекта уже использовалась как курсовая работа и является рабочей основой для дальнейшего развития. Открытые задачи и идеи следующих итераций ведутся в GitHub Issues; README описывает текущее состояние приложения, а не исторический план разработки.

## Проверка сборки

Для pull request и изменений в `master` настроен GitHub Actions workflow, выполняющий `dotnet restore` и Release-сборку на .NET 9. Это позволяет быстро обнаруживать изменения, которые ломают сборку на чистом checkout.
